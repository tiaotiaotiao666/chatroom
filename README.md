# TCP 多人聊天室系统

基于 Node.js 和 TypeScript 构建的实时多人聊天室应用，采用 C/S（客户端/服务器）架构，支持局域网内多客户端同时在线交流。

## ✨ 核心特性

- ✅ **多人实时聊天** - 消息即时广播给所有在线用户
- ✅ **昵称系统** - 支持自定义昵称，自动检测重复
- ✅ **私聊功能** - 使用 `@用户名` 进行一对一私聊
- ✅ **在线用户查看** - 随时查看当前在线的用户列表
- ✅ **心跳检测机制** - 每30秒发送心跳，防止连接超时断开
- ✅ **自动断线重连** - 网络波动时自动重连，指数退避策略
- ✅ **优雅退出处理** - Ctrl+C 或 `/quit` 命令安全退出
- ✅ **局域网支持** - 支持同一局域网内多设备互联

## 🛠️ 技术栈

- **运行时**: Node.js (推荐 v14+)
- **语言**: TypeScript (类型安全)
- **网络协议**: TCP (`net` 模块)
- **命令行交互**: `readline` 模块
- **依赖管理**: npm

## 🔍 核心功能详解

### 1. 昵称系统

- **唯一性检查**: 服务器维护 `usedNicknames` 集合，防止昵称重复
- **自动分配**: 如果未输入昵称，自动分配 `用户{时间戳}`
- **释放机制**: 用户断开连接后，昵称自动释放供他人使用

### 2. 心跳机制

**为什么需要心跳？**
- TCP 连接可能因长时间无活动被防火墙或路由器切断
- 心跳可以保持连接活跃，及时发现断开的连接

**工作原理：**
```
客户端                    服务器
  | -- PING (每30秒) --> |
  | <-- PONG (立即响应) - |
  |                      |
  |  如果60秒未收到PONG   |
  |  判定连接断开         |
```

### 3. 自动重连

**重连策略：**
- 首次重连：3秒后
- 第二次：6秒后
- 第三次：12秒后
- ...以此类推，最大间隔30秒
- 最多尝试10次（可配置为无限重连）

**指数退避算法：**
```typescript
delay = min(3000 × 2^(重试次数-1), 30000)
```

### 4. 消息广播

**群聊消息流程：**
```
用户A发送消息
    ↓
服务器接收
    ↓
遍历所有在线客户端
    ↓
发送给除发送者外的所有用户
```

**私聊消息流程：**
```
用户A发送 @用户B 消息
    ↓
服务器解析目标用户
    ↓
仅发送给用户B
    ↓
向用户A确认发送成功
```

## ❓ 常见问题 (FAQ)

### Q1: 无法连接到服务器？

**排查步骤：**

1. **确认服务器已启动**
   ```bash
   # 检查服务器是否在运行
   netstat -ano | findstr :3500
   ```

2. **检查防火墙设置**
   - Windows: 允许端口 3500 的入站连接
   - macOS/Linux: 检查 `ufw` 或 `iptables` 规则

3. **验证 IP 地址和端口**
   ```bash
   # 测试网络连通性
   ping <服务器IP>
   
   # 测试端口是否开放
   telnet <服务器IP> 3500
   ```

4. **确认客户端参数正确**
   ```bash
   # 正确格式
   npx ts-node 客户端.ts 192.168.1.100 3500
   ```

### Q2: Windows 防火墙阻止连接？

**解决方案：**

以管理员身份运行 PowerShell，执行：

```powershell
# 添加入站规则允许端口 3500
New-NetFirewallRule -DisplayName "ChatRoom Server" -Direction Inbound -LocalPort 3500 -Protocol TCP -Action Allow

# 验证规则已添加
Get-NetFirewallRule -DisplayName "ChatRoom Server"
```

或者通过图形界面：
1. 打开 "Windows Defender 防火墙"
2. 点击 "高级设置"
3. 选择 "入站规则" → "新建规则"
4. 选择 "端口" → TCP → 特定本地端口: 3500
5. 选择 "允许连接" → 完成

### Q3: 端口被占用？

**查找占用进程：**

```bash
# Windows
netstat -ano | findstr :3500
tasklist | findstr <PID>

# macOS/Linux
lsof -i :3500
```

**解决方案：**

1. **关闭占用程序**
   ```bash
   # Windows
   taskkill /F /PID <PID>
   
   # macOS/Linux
   kill -9 <PID>
   ```

2. **修改端口号**
   
   编辑 `聊天室.ts`：
   ```typescript
   const PORT = 3501; // 改为其他可用端口
   ```
   
   客户端连接时指定新端口：
   ```bash
   npx ts-node 客户端.ts localhost 3501
   ```

### Q5: 局域网其他设备无法连接？

**完整排查流程：**

1. **确认服务器监听所有接口**
   ```typescript
   // 聊天室.ts 中应该是：
   server.listen(PORT, '0.0.0.0')  // ✅ 正确
   // 而不是：
   server.listen(PORT, 'localhost') // ❌ 错误
   ```

2. **获取本机局域网 IP**
   ```bash
   # Windows
   ipconfig
   
   # macOS/Linux
   ifconfig
   
   # 找到类似 192.168.x.x 或 10.x.x.x 的地址
   ```

3. **确认所有设备在同一网段**
   ```bash
   # 在其他设备上 ping 服务器
   ping 192.168.1.100
   ```

4. **其他设备连接时使用服务器 IP**
   ```bash
   # 手机/其他电脑
   npx ts-node 客户端.ts 192.168.1.100 3500
   ```

5. **检查路由器设置**
   - 确保没有启用 "AP 隔离" 功能
   - 确认所有设备连接到同一 WiFi/交换机

### Q6: 消息显示混乱或重叠？

**原因：** readline 模块在处理并发输入输出时的正常现象

**解决方案：**
- 这是设计行为，不影响功能
- 收到服务器消息时会自动清除当前输入行并重新显示提示符
- 建议不要在输入长消息时期待其他人发送消息

### Q7: 断开后没有自动重连？

**检查项：**

1. **确认使用了正确的退出方式**
   - 使用 `/quit` 或 Ctrl+C 是优雅退出，不会重连
   - 只有异常断开才会触发重连

2. **检查重连次数限制**
   ```typescript
   // 客户端.ts 中可查看配置
   const MAX_RECONNECT_ATTEMPTS = 10; // 最多重连10次
   ```

3. **查看控制台输出**
   - 重连时会显示：`[系统] X秒后尝试第 N 次重连...`
   - 达到上限会显示：`已达到最大重连次数，停止重连`

## 🛡️ 安全考虑

### 当前版本的局限性

⚠️ **重要提示：** 本项目主要用于学习和实验，存在以下安全问题：

1. **明文传输** - 所有消息未加密，可能被网络嗅探
2. **无身份验证** - 任何人都可以连接并使用任意昵称
3. **无消息过滤** - 可能传播不当内容
4. **无频率限制** - 可能被恶意刷屏攻击
5. **无连接数限制** - 可能导致服务器资源耗尽

### 生产环境建议

如果要在真实环境中使用，建议添加：

- 🔐 **TLS/SSL 加密** - 使用 `tls` 模块替代 `net` 模块
- 👤 **用户认证系统** - 用户名密码或 Token 验证
- 🚫 **内容过滤** - 敏感词检测和屏蔽
- ⏱️ **速率限制** - 限制单用户消息频率
- 🔢 **最大连接数** - 限制同时在线客户端数量
- 📋 **日志记录** - 记录关键操作便于审计
- 🛡️ **IP 白名单/黑名单** - 控制访问来源
